## 5. Nits (non-blocking)

1. **Structural-overlap term is degenerate in all tool paths.** `check_novelty` implements §7 structural Jaccard correctly, and it's unit-tested — but neither `hypothesis_propose` nor `explore_methods` passes an `edge_set`, so `structural_overlap` is always 0 in real flows (N silently collects `w2·1`). The plan never specifies free-text→graph grounding, so this is a spec gap rather than a bug — but N's "bounded per §7" claim currently rests on 2 of 3 terms. Recommend recording the intended grounding design before Phase 5.
2. **`max_cos` archive isn't family-scoped for graph nodes.** Plan §7 says "archive_embs in family"; code filters only *hypotheses* by family ([novelty.py](./src/spark_mcp/novelty.py:58)) while *all 153 graph nodes* count regardless of family ([novelty.py](./src/spark_mcp/novelty.py:43)). Reading the method graph as shared vocabulary is defensible, but it's a literal deviation from §7 — worth one recorded sentence.
3. **43% of ASSUMES/FAILS_WHEN seed refs (226/524) don't resolve** to concept nodes (e.g. `skewness_preference`, `value_traps`, `trending_markets`) and are dropped into an aggregate counter; per-card misses are invisible. All 101 techniques remain grounded via the resolved subset, so nothing breaks — but either the concept layer should grow toward the referenced vocabulary or misses should be logged per card.
4. **Cosmetic:** `explore` pool size `min(n, max(2k, k+5))` ([explore.py](./src/spark_mcp/explore.py:357)) is an unplanned selection-mechanics constant that belongs in config or a comment; `hybrid_recall` signature defaults (50/50/60) duplicate config defaults (callers pass config explicitly, so harmless); seed import derives only 3 of the 6 active predicates (`SOLVES`/`DIAGNOSES`/`DERIVED_FROM` accepted-but-unpopulated — fine, just noting).
