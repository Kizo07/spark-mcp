## Implementer deviations — assessment

1. **P-value form: reasoning CORRECT, implementation CORRECT.** `psr()/dsr()` return Bailey–LdP Φ(z) confidence; gate computes `p = 1 − Φ(z)`, passes iff `p < alpha` with `sr > 0` (`service.py:595,601`). Promoting on Φ(z) < 0.05 would indeed promote below-null Sharpe. Both forms asserted in tests (`test_gates_service.py:458-459`). Spot check: DSR(1.5; T=1000, M=10) = 0.051975 → p = 0.948 → fail, as the code narrative claims.
2. **Null-scale V + MinBTL binary search: verified as documented.** All pins reproduced to ~1e-15; quadrature confirms the EM-approximation context (M=10: impl 1.574598 vs exact E[max] 1.538753 — matches the code's cited 1.53875); MinBTL pins match brute-force scan; `clears()` monotone on a 210-curve grid. Nits N3: docstring says "binary search over dsr()" but `clears()` inlines the z-inequality (algebraically identical, but drift risk); monotonicity justification is imprecise for skew>0 (holds in practice, unproven in general).
3. **Lexical fallback: acceptable**, deterministic, always logs `basis`.
4. **`archive_status` absent: acceptable Phase-5 deferral**; `spend_summary()` + `report_write` cost section verified present (`budgets.py:72-82`, `server.py:535-540`, MCP test asserts it).
5. **Live-peer half: recharacterized** (see criterion 1) — peer exists, contract mismatch is the blocker. Correct fallback chosen.
6. **fail_closed rollback: verified** (`test_gates_service.py:707-723`: no trial, no dispatch, spend rolled back). Nit N4: `budgets.py` docstring says "checks BEFORE the trial row" — actually inserted-then-rolled-back; same end state, imprecise wording. Related: in `log_outcome`, fail_closed refusal rolls back an *already-happened* run's accounting (unlike `backtest_run` where nothing happened yet) — over-budget OOB runs become unattested.
